# PDF 多模态画像导入计划

## 目标

在已有简历导入草稿链路上，将 PDF 按页渲染为临时 PNG 图片并交给支持视觉输入的模型；DOCX、TXT 和 Markdown
继续使用正文输入。两条路径都只返回可校对草稿，不保存原文件、不保存中间图片、不创建画像版本。

## 实施范围

1. 更新 `ProfileParserPort`，同时支持正文和页面图片输入；模型输出继续通过 `ProfileImportView` 校验。
2. 使用 pypdfium2 和 Pillow 在请求生命周期内渲染 PDF，保留 10 MiB、4 页、加密/损坏文件和超时等边界。
3. PDF 与推荐共用 `JOBPICKY_LLM_MODEL`；该模型必须支持视觉输入，未配置时 PDF 导入明确返回依赖未配置错误。
4. 更新画像页的上传说明、处理中状态、错误提示和相关前端测试。

## 明确不做

- 不保存原始简历、临时图片、完整模型输入或模型原始响应。
- 不改变画像草稿需要用户确认后才能保存的语义。
- 不支持旧版 `.doc`，不引入异步导入任务或新的数据库表。
- 不在普通测试中调用真实视觉模型。

## 验收

- 有效 PDF 能被渲染成 PNG 页面并以多模态消息发送，扫描页不再因没有文字层而被服务端提前拒绝。
- 超过 4 页的 PDF 在渲染和模型调用前被拒绝，并返回可操作的页面提示。
- DOCX、TXT 和 Markdown 仍通过文本输入解析；文件、图片和模型输出错误均显式返回。
- 相关后端、前端和契约测试通过，前端明确提示 PDF 的页面识别和草稿未保存语义。
