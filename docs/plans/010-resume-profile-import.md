# 简历上传生成画像草稿计划

> 状态：已完成的初始文本导入基线。PDF 页面视觉解析扩展见
> [011-multimodal-pdf-profile-import.md](011-multimodal-pdf-profile-import.md)。

## 目标

在现有“我的求职画像”入口增加简历上传：登录用户上传 PDF、DOCX、TXT 或 Markdown 后，由现有大模型配置
同步返回可校对画像草稿；用户确认后继续通过现有画像保存接口生成不可变版本。

## 实施阶段

1. 契约与边界：新增 `ProfileImportDraft`、`ProfileImportView` 和
   `POST /api/v1/user/profile-imports`，固定格式、大小、页数、文本长度、错误与隐私语义。
2. 后端纵向切片：校验上传文件，提取可读文本，调用结构化模型解析器并校验输出；复用现有画像 Service、
   `ProfileParserPort`、模型配置和统一错误响应，不新增数据库表、队列或导入运行。
3. 前端入口：在原画像页加入原生文件选择入口和解析状态；成功后把草稿带入现有分步表单，展示警告并要求
   用户逐项确认，保存动作仍调用原 `PUT /profiles/current`。
4. 验证：自动覆盖文件类型/大小/空文本、DOCX/PDF 文本提取、非法模型输出、身份边界和 multipart
   OpenAPI，并运行后端完整检查；前端页面由用户手动验收，根据反馈继续调整。

## 明确不做

- 不保存原始简历或解析任务，不新增迁移。
- 不自动保存画像、覆盖当前版本、扣积分或发起推荐。
- 不支持旧版 `.doc`、扫描版 PDF/OCR、图片简历或 AI 对话；真实样本证明需要时再增加。
- 不为尚未出现的延迟或恢复问题引入异步 Worker。

## 验收

- 支持格式返回结构化草稿和中文警告，模型内容可追溯到上传文本。
- 不支持、过大、加密/损坏、无文本和模型非法输出显式失败。
- 原文件、联系方式和完整模型输入不进入日志、普通画像响应或持久化。
- 用户修改并明确保存前，当前画像与推荐状态均不变化。
