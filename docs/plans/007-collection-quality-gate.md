# collection-quality-gate 实施计划

## 目标

在“解析器输出 → 岗位目录入库”之间增加最小质量门，避免把结构合法但事实错误的结果写入岗位库；解析失败或不可信时使用表格事实兜底，并保留失败原因。

## 当前问题

- 解析器异常、空结果或无标题时，当前记录直接不产生岗位，不入库。
- 只做 Schema 校验，不判断标题、JD 是否真的是岗位事实。
- `merge_job_fields()` 让解析器招聘类型覆盖表格批次。
- `CollectedJob.metadata` 当前未持久化，退化原因会丢失。

最新样本中，微信结果大量需要人工检查；公司招聘官网存在多个标题均为“职位详情”的结果。见 `artifacts/collection-review/` 最新结果目录。

## 核心决策

每个表格行只产生一种结果：

```text
ACCEPT_PARSED      可信解析结果
FALLBACK_TO_TABLE  解析失败或不可信，使用表格事实
SKIP_STALE         明确过期，不入岗位库
```

字段按职责合并，不做整条记录的“表格覆盖”或“解析器覆盖”：

- 可信解析：`title`、`description`、岗位详情链接、岗位级地点/薪资等使用解析器；
- 招聘类型优先使用解析器明确返回的值；解析器未返回时才使用表格归一化值，无法归一化的明确值保持为空；原始 `batch` 保留在 metadata；
- 解析器缺失字段再使用表格字段；冲突写入质量原因；
- 退化记录：标题用 `job_directions`，缺失时才用公司名；JD 用表格岗位摘要；原始投递/文章链接同时作为详情和投递入口；
- 日期缺失不代表过期；明确截止时间已过才跳过，发布时间阈值必须可配置且保守。

## 范围

实现：

1. 新增 `src/jobpicky/collection/quality.py`，只放质量判断和表格兜底构造。
2. `pipeline.py` 在调用解析器前执行来源策略，在解析后执行质量判断。
3. 初始将 `WECHAT`、`COMPANY_WEBSITE`、`COMPANY_RECRUITMENT_SITE` 配置为表格兜底策略；保留解析器代码，后续可按平台重新启用。
4. 为可信、退化、跳过和冲突记录稳定的 `collection_mode`、`quality_reasons` 等 metadata。
5. 为岗位 metadata 增加最小 JSONB 持久化及迁移，保证退化原因和表格来源可追溯。
6. 增加质量门、退化入库、过期跳过、平台禁用和字段优先级测试。

## 不做

- 不重写或删除现有解析器，不引入模型或 LLM 评分。
- 不做未知网站探索、跨来源合并、历史岗位关闭、采集编排或 HTTP API。
- 不全量重新读取或改写已有 JSON/CSV artifact。
- 不把不确定字段强行补成完整事实。

## 实现安排

1. 增加质量结果和平台策略的最小内部类型；复用现有 `SpreadsheetRow`、`CollectedJob` 和 `CollectionBatch`。
2. 增加表格兜底构造器；失败也生成可检索、可投递的岗位记录。
3. 接入 pipeline：先跳过明确过期行，再按策略决定是否调用解析器，最后执行质量门并形成单来源批次。
4. 持久化 metadata，保留原始链接、表格行号、批次、退化模式和原因。
5. 用少量最新样本和脱敏 fixture 验证；运行完整 ruff、format、mypy、pytest 及 PostgreSQL 集成测试。

## 验收

- 可信解析结果的岗位标题和 JD 不被表格摘要覆盖。
- 招聘类型以解析器明确事实为准，解析器缺失时才使用表格兜底；原始招聘批次可追溯并按单元拆分筛选。
- 解析异常、空结果、泛标题、文章标题、多岗位合并等情况退化入库，不静默丢弃。
- 明确过期岗位不入库，并记录跳过原因和数量。
- 配置为表格兜底的平台不发起网络解析。
- 退化记录可通过表格摘要和原始链接检索/投递。
- 重复执行仍保持岗位身份幂等；不完整批次不关闭历史岗位。
