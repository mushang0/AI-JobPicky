## 完整链路

### 1. 建立岗位数据库

爬虫从不同公司招聘官网获取岗位，并统一保存为结构化数据：

```json
{
  "job_id": "job_001",
  "company": "某公司",
  "title": "嵌入式软件工程师",
  "cities": ["深圳"],
  "jd": "岗位职责和任职要求",
  "job_detail_url": "岗位详情链接",
  "apply_url": "岗位直接投递链接",
  "status": "OPEN"
}
```

PostgreSQL保存完整岗位数据，同时对以下字段建立索引：

* 城市、岗位状态、招聘类型：普通数据库索引；
* 岗位名称和JD：全文索引；
* 岗位名称和JD拼接后的文本：生成Embedding，存入pgvector。

每个岗位第一版只生成一个向量，不需要复杂切块。

---

### 2. 解析用户需求

用户上传简历并输入模糊需求：

> 想找深圳的嵌式或端侧AI岗位，会C++和FPGA，不考虑测试。

大模型将简历和需求转成结构化JSON：

```json
{
  "target_cities": ["深圳"],
  "target_roles": ["嵌入式开发", "端侧AI"],
  "skills": ["C++", "FPGA"],
  "excluded_roles": ["测试"],
  "education": "硕士"
}
```

这里大模型负责理解自然语言，程序负责校验JSON格式。

---

### 3. 规则硬筛选

程序先查询结构化数据库，排除明确不符合的岗位：

```text
岗位必须开放
城市必须符合
招聘类型必须符合
学历要求必须符合
排除测试岗
```

硬条件不能交给大模型，因为必须稳定、准确、可复现。

---

### 4. RAG召回岗位

对硬筛选后的岗位同时进行两种检索：

* **全文搜索**：匹配C++、FPGA、嵌入式等明确关键词；
* **向量搜索**：匹配语义相关岗位，例如“底层软件开发”和“嵌入式开发”。

两种结果合并、去重并计算综合召回分数。

不固定召回岗位数量，而是设置最低阈值：

```text
全文相关度 ≥ 阈值
或
向量相似度 ≥ 阈值
```

阈值要通过测试集调整，使召回结果中大部分岗位相关，同时允许少量误召回，交给后面的大模型排除。

---

### 5. 取回候选岗位

RAG返回候选岗位的`job_id`和召回分数。

程序根据`job_id`从数据库取出：

```text
岗位名称
公司
城市
JD
岗位详情链接
投递链接
```

然后把用户画像和候选岗位JD一起交给大模型。

---

### 6. 大模型评估和精排

大模型逐个判断：

* 用户能力是否满足岗位要求；
* 项目经历是否与岗位职责相关；
* 是否只是关键词碰巧相同；
* 岗位是否符合用户目标方向；
* 用户有哪些优势和能力缺口。

大模型只输出结构化结果：

```json
{
  "results": [
    {
      "job_id": "job_001",
      "matched": true,
      "score": 88,
      "reason": "C++和FPGA经验与岗位要求相关，项目经历涉及底层实时系统开发。",
      "matched_skills": ["C++", "FPGA"],
      "gaps": ["简历中未明确体现Linux驱动经验"]
    },
    {
      "job_id": "job_002",
      "matched": false,
      "reason": "该岗位主要是软件测试，与用户排除条件冲突。"
    }
  ]
}
```

大模型不能修改岗位事实，也不能自己生成岗位链接。

---

### 7. 程序组装最终结果

程序：

1. 删除`matched=false`的岗位；
2. 按模型评分和检索分数组合排序；
3. 根据`job_id`再次读取数据库中的真实岗位数据；
4. 将岗位事实与模型生成的推荐理由拼接；
5. 返回给前端。

最终数据：

```json
{
  "job_id": "job_001",
  "company": "某公司",
  "title": "嵌入式软件工程师",
  "cities": ["深圳"],
  "jd": "真实岗位JD",
  "job_detail_url": "真实详情链接",
  "apply_url": "真实投递链接",
  "match_score": 88,
  "reason": "C++和FPGA经验与岗位要求相关。",
  "gaps": ["缺少Linux驱动经验"]
}
```

---

## Agent负责什么

Agent负责串联整个流程，并调用不同工具：

```text
读取用户画像
→ 解析本次需求
→ 调用硬筛选工具
→ 调用全文和向量检索工具
→ 获取候选岗位详情
→ 调用大模型评估工具
→ 保存推荐结果
→ 返回前端
```

Agent不负责具体检索算法，也不保存岗位数据。它负责判断当前应该调用哪个工具，以及各步骤的执行顺序。

## 最终分工

```text
数据库：保存真实岗位和用户数据
规则：执行城市、学历、状态等硬筛选
RAG：通过全文搜索和向量搜索召回候选岗位
大模型：解析需求、判断匹配、排除误召回、生成推荐理由
Agent：调用并组织以上步骤
程序后端：校验结果、读取真实JD和链接、组装前端数据
```
