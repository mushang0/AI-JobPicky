# 飞书招聘数据采集：Linux 服务器部署说明

本文说明如何把飞书多维表格采集器部署到 Linux 服务器，并由 systemd 每天自动执行。

## 一、先理解整体流程

浏览器只在第一次授权时使用，服务器以后不需要浏览器：

```text
本机浏览器完成 OAuth 授权
        ↓
本机保存 access_token + refresh_token
        ↓ 通过安全文件传输复制一次
Linux 服务器每天执行 sync
        ↓
自动刷新 token → 读取飞书 → 解析招聘链接 → PostgreSQL 幂等入库
```

服务器不会登录飞书网页，也不会保存 Cookie。`refresh_token` 过期或被撤销时，才需要在本机
重新授权，再把新的 token 文件复制到服务器。

## 二、准备条件

假设服务器使用以下目录和用户：

```text
项目目录：/opt/jobpicky
运行用户：jobpicky
配置文件：/etc/jobpicky/feishu.env
Token 文件：/var/lib/jobpicky/feishu-token.json
锁文件：/var/cache/jobpicky/feishu.lock
```

服务器需要具备：

1. Linux 和 systemd；
2. Python 环境以及项目依赖；
3. PostgreSQL，并且服务器能连接数据库；
4. `jobpicky` 用户对项目、Token 目录和锁目录有正确权限；
5. 服务器能访问飞书 API 和招聘网站。

## 三、本机只做一次 OAuth 初始化

本机项目目录是 `/Users/joy/Documents/toyproject`。确认 [`.env`](/Users/joy/Documents/toyproject/.env)
中已经填写：

```dotenv
JOBPICKY_FEISHU_APP_ID=你的 App ID
JOBPICKY_FEISHU_APP_SECRET=你的 App Secret
JOBPICKY_FEISHU_APP_TOKEN=源表 URL 中的 app token
JOBPICKY_FEISHU_TABLE_ID=源表 URL 中的 table 参数
JOBPICKY_FEISHU_VIEW_ID=源表 URL 中的 view 参数
JOBPICKY_FEISHU_SINCE_DATE=2026-06-20
JOBPICKY_FEISHU_TOKEN_FILE=~/.config/jobpicky/feishu-token.json
```

执行一次授权：

```bash
cd /Users/joy/Documents/toyproject
set -a
source .env
set +a
uv run python scripts/feishu.py auth
```

浏览器打开后，用有权限查看源表的飞书账号同意授权。授权成功后，脚本会把两个 token 保存到：

```text
/Users/joy/.config/jobpicky/feishu-token.json
```

检查权限，不要打印文件内容：

```bash
stat -f '%Sp %Lp %N' /Users/joy/.config/jobpicky/feishu-token.json
```

结果应为 `600`。不要把这个文件提交到 Git、发到聊天中或复制到不受信任的位置。

## 四、把代码和配置放到服务器

以下命令中的 `SERVER` 替换成服务器地址。项目可以用 Git、压缩包或其他发布方式复制到
`/opt/jobpicky`，这里不限定具体发布工具。

在服务器上创建目录和用户：

```bash
sudo useradd --system --home /var/lib/jobpicky --shell /usr/sbin/nologin jobpicky
sudo install -d -o jobpicky -g jobpicky /var/lib/jobpicky
sudo install -d -o jobpicky -g jobpicky /var/cache/jobpicky
sudo install -d -o root -g root -m 0755 /etc/jobpicky
```

把本机 token 文件安全复制到服务器：

```bash
scp /Users/joy/.config/jobpicky/feishu-token.json SERVER:/tmp/feishu-token.json
ssh SERVER 'sudo install -o jobpicky -g jobpicky -m 600 /tmp/feishu-token.json /var/lib/jobpicky/feishu-token.json && rm /tmp/feishu-token.json'
```

如果服务器禁止直接使用 `scp`，可以使用服务器已有的安全文件传输方式，最终必须满足：

```text
文件：/var/lib/jobpicky/feishu-token.json
拥有者：jobpicky
权限：600
```

## 五、配置服务器环境变量

复制模板：

```bash
sudo install -o root -g root -m 600 \
  /opt/jobpicky/deploy/systemd/feishu.env.example \
  /etc/jobpicky/feishu.env
```

编辑配置文件：

```bash
sudoedit /etc/jobpicky/feishu.env
```

至少填写或确认以下内容：

```dotenv
JOBPICKY_DATABASE_URL=postgresql+asyncpg://用户名:密码@数据库地址:5432/数据库名
JOBPICKY_FEISHU_APP_ID=你的 App ID
JOBPICKY_FEISHU_APP_SECRET=你的 App Secret
JOBPICKY_FEISHU_APP_TOKEN=从源表 URL 复制
JOBPICKY_FEISHU_TABLE_ID=从源表 URL 的 table 参数复制
JOBPICKY_FEISHU_VIEW_ID=从源表 URL 的 view 参数复制
JOBPICKY_FEISHU_SINCE_DATE=2026-06-20
JOBPICKY_FEISHU_TOKEN_FILE=/var/lib/jobpicky/feishu-token.json
JOBPICKY_FEISHU_LOCK_FILE=/var/cache/jobpicky/feishu.lock
JOBPICKY_FEISHU_OAUTH_SCOPE="bitable:app:readonly offline_access"
```

其中 App Secret、数据库密码和 token 都属于敏感信息。配置文件应保持：

```bash
sudo chown root:root /etc/jobpicky/feishu.env
sudo chmod 600 /etc/jobpicky/feishu.env
```

## 六、执行数据库迁移

新增的 `feishu_sync_state` 表用于记录每条飞书记录的 hash、处理状态和错误信息。第一次部署
或升级代码后执行：

```bash
sudo -u jobpicky bash -lc '
  set -a
  source /etc/jobpicky/feishu.env
  set +a
  cd /opt/jobpicky
  /opt/jobpicky/.venv/bin/alembic upgrade head
'
```

迁移成功后，检查当前版本：

```bash
sudo -u jobpicky bash -lc '
  set -a
  source /etc/jobpicky/feishu.env
  set +a
  cd /opt/jobpicky
  /opt/jobpicky/.venv/bin/alembic current
'
```

输出应包含最新迁移版本 `0013_feishu_sync_state`。

## 七、安装并启用 systemd

安装 service 和 timer：

```bash
sudo install -o root -g root -m 644 \
  /opt/jobpicky/deploy/systemd/jobpicky-feishu.service \
  /etc/systemd/system/jobpicky-feishu.service
sudo install -o root -g root -m 644 \
  /opt/jobpicky/deploy/systemd/jobpicky-feishu.timer \
  /etc/systemd/system/jobpicky-feishu.timer
sudo systemctl daemon-reload
```

先检查 unit 文件是否被 systemd 接受：

```bash
sudo systemd-analyze verify \
  /etc/systemd/system/jobpicky-feishu.service \
  /etc/systemd/system/jobpicky-feishu.timer
```

没有输出通常表示语法检查通过。若有输出，先修复错误，不要直接启用定时器。

## 八、先手动测试，再启用每天定时

### 1. 测试一次完整 service

第一次建议直接启动一次 service：

```bash
sudo systemctl start jobpicky-feishu.service
sudo systemctl status jobpicky-feishu.service --no-pager
sudo journalctl -u jobpicky-feishu.service -n 100 --no-pager
```

成功时日志最后会有类似摘要：

```text
sync complete records=... succeeded=... failed=... skipped=... unchanged=... created=... updated=...
```

`failed` 不应被忽略。如果失败，先看日志中的记录级错误；修复后再次执行 service，失败记录会
根据同步状态重试，未变化且已成功的记录不会再次访问招聘网站。

### 2. 启用每天执行

```bash
sudo systemctl enable --now jobpicky-feishu.timer
sudo systemctl status jobpicky-feishu.timer --no-pager
systemctl list-timers --all | grep jobpicky-feishu
```

当前 timer 配置的含义：

- 每天约凌晨 03:15 执行；
- `RandomizedDelaySec=15m` 允许在 15 分钟内随机延迟，避免固定时间集中访问；
- `Persistent=true` 表示服务器关机错过任务后，重新启动会补执行；
- service 是 `Type=oneshot`，一次同步完成后进程退出；
- 文件锁会阻止同一台服务器上的重复运行。

查看下一次执行时间：

```bash
systemctl show jobpicky-feishu.timer \
  -p ActiveState -p NextElapseUSecRealtime -p LastTriggerUSec
```

注意：`systemctl start jobpicky-feishu.timer` 只会启动计时器，不会立即执行采集。要立即验证采集，
使用 `systemctl start jobpicky-feishu.service`。

## 九、如何验证“飞书 → 解析 → 入库”全流程

脚本提供 `--limit`，可以先只处理一条记录，验证成功后再让 systemd 处理完整候选集：

```bash
sudo -u jobpicky bash -lc '
  set -a
  source /etc/jobpicky/feishu.env
  set +a
  cd /opt/jobpicky
  /opt/jobpicky/.venv/bin/python scripts/feishu.py sync --limit 1
'
```

这条命令会依次执行：

1. 读取服务器上的 token 文件，必要时自动刷新；
2. 从飞书读取最新记录和投递链接；
3. 将飞书字段转换成 `SpreadsheetRow`；
4. 使用现有链接分类和招聘网站解析器；
5. 使用现有 `PostgresJobCatalog` 幂等写入 PostgreSQL；
6. 写入 `feishu_sync_state`，记录成功、跳过或失败原因。

如果第一条记录没有有效投递链接，日志可能显示 `skipped`，这不代表 API 失败。此时应从飞书候选
记录中选择一条有投递链接的记录做测试，或者直接启动不带 `--limit` 的 service。

验证完成后查看：

```bash
sudo journalctl -u jobpicky-feishu.service -n 100 --no-pager
```

不要根据一次不完整读取删除岗位或关闭岗位。飞书源表删除和岗位归档是两个独立问题。

## 十、常见问题

### 服务器没有浏览器怎么办？

不需要。浏览器只用于本机第一次 `auth`。服务器执行的是无浏览器的 `sync`，使用保存的 refresh token
自动换取新的 access token。

### Token 过期怎么办？

先看日志。如果 refresh token 被撤销或已经过期，在本机重新执行 `auth`，再把新的
`feishu-token.json` 以 `600` 权限复制到 `/var/lib/jobpicky/`。

### 返回 403 怎么办？

确认应用已发布、用户仍能打开源表、应用权限已开通，并且授权账号就是有源表查看权限的账号。
应用不能绕过源表权限；必要时需要源表所有者把应用加入可访问范围。

### 定时器没有执行怎么办？

依次检查：

```bash
systemctl is-enabled jobpicky-feishu.timer
systemctl is-active jobpicky-feishu.timer
systemctl list-timers --all | grep jobpicky-feishu
journalctl -u jobpicky-feishu.timer -n 50 --no-pager
journalctl -u jobpicky-feishu.service -n 100 --no-pager
```

### 如何临时停止每天任务？

```bash
sudo systemctl disable --now jobpicky-feishu.timer
```

这不会删除数据库数据，也不会删除 token 文件。恢复时执行：

```bash
sudo systemctl enable --now jobpicky-feishu.timer
```
